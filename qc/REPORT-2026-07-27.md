## This run: closed a real, live chronology/spoiler-leak bug

**Found:** `generateImagePrompt`'s prior-events filter
(`promptService.ts`, chronology block) is supposed to gate the visual
bible's chronology list so a page's prompt only sees events that happened
*before* it — the file's own docstring states the purpose explicitly:
"the ordered event list so page 3 can't show what page 10 reveals." The
filter parses each entry against `/^Page (\d+):/` and compares the captured
number to the current page. But when an entry does **not** match that
format, the fallback returned `true` — unconditionally "already happened" —
instead of being excluded as unorderable. Any chronology entry the LLM
returns without the "Page N:" prefix (a real possibility: the schema asks
for that format but doesn't enforce it structurally) leaked into every
single page's prompt regardless of when it actually occurs in the story,
defeating the gate for exactly the entries most likely to be malformed.

This wasn't latent — `storyBibleBoundary.test.ts`'s own chronology-gate test
had a fixture entry ("The sea parts", deliberately left unprefixed) and
asserted it appears in **page 1's** prompt, with a comment reading
"un-numbered entries always pass." That assertion documented the bug as
intended behavior.

**Why it matters:** `generateImagePrompt` is called from `readingPipeline.ts`
(the live transcription stage `gatePipeline.ts`'s `extractAndStorePages` →
`transcribeBook` flow uses for every book), not just the orphaned
`pipelineService.ts` path — so this is a production spoiler leak, not dead
code.

**Fix:** flipped the fallback from `true` to `false` — an entry that can't
be parsed and ordered is excluded from "already happened," not assumed to
qualify. One line changed (`promptService.ts`).

**Tests:** updated the existing chronology-gate test in
`storyBibleBoundary.test.ts` — removed the assertion that the unprefixed
entry leaks on page 1, added a loop asserting it never appears on *any*
page's prompt. No test count change (tightened in place, matching the shape
of a behavior correction rather than new coverage).

**Also this run:** updated `qc/AUDIT-RECONCILIATION-2026-07-17.md` with a
